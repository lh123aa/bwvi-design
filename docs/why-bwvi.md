# Why BWVI? — 从现有方案学到的教训

## 从 Huashu-Design 学到的

**好的：**
- 设计哲学的系统化表达（5 流派 × 20 风格）
- Junior Designer 的分步确认流程
- 品牌资产协议的 5 步硬流程
- 反 AI slop 的细致清单

**学到的教训：**
- 58KB 知识全部塞进上下文行不通
- 设计资产（logo、产品图）不应是指令中的假设，而是协议中的一等公民
- 自评有系统性偏差，需要交叉验证
- 知识需要版本管理，不能每次都是"最新版"

## 从 Open-Design 学到的

**好的：**
- 多 Agent 自动检测（13 种 CLI）
- 129 套设计系统即开即用
- 媒体生成管道（图片/视频/音频）
- Skill 文件化的可扩展架构

**学到的教训：**
- Node 24 + pnpm + daemon + SQLite + Electron ≠ 开发者友好
- 模板越多同质化越严重
- 品牌数据快照必然过时
- 60+ skill 文件的管理成本 > 收益

## 从 Claude Design 学到的

**好的：**
- artifact-first 的输出模型
- 沙箱预览 + 一键保存

**学到的教训：**
- 锁定在 Anthropic 生态不可持续
- 无品牌资产管道 = 所有产出都是"AI 通用风"
- 无评审体系 = 用户自己判断质量

## BWVI 的核心赌注

**赌 Agent 会成为设计师的主要工具。**
不只是"写代码"的工具，而是"做设计决策"的工具。

如果这个赌注对了，那么：
- 不需要 Web UI（Agent 的聊天界面就是 UI）
- 不需要 daemon（Agent 本身就是运行时）
- 不需要模板（Agent 本身就是生成引擎）
- 需要的是：决策框架、知识体系、质量保障

如果这个赌注错了，那么：
- BWVI 的 CLI 和 MCP server 仍然可以作为设计辅助工具
- 不会浪费大量基础设施投资（不像 Open-Design 那样搭了整个平台）
